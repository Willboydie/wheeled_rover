1. SUMMARY
--------------------------------------------------------------------------------
  Motor type        Brushed permanent-magnet DC, carbon brushes, copper winding
  Gearbox           25mm metal multi-stage spur gearbox, 4.4:1 to 500:1
  Feedback          Magnetic incremental Hall encoder on the MOTOR shaft,
                    2 channels (A/B quadrature), 11 pulses/motor rev/channel
  Supply variants   12V DC or 24V DC (the 6V table in the listing is reference only)
  Motor speed       6000 RPM before gearbox (no load, at rated voltage)
  Control           PWM through an external brushed-DC H-bridge driver
  Position sensing  INCREMENTAL ONLY: no absolute position, no index pulse.
                    Homing is needed if absolute position matters.

  In plain terms: a small geared DC motor with a sensor on the back that ticks
  11 times per motor revolution. Count the ticks to get speed and relative
  position. The gearbox sets how many ticks you get per output revolution.

  !! LOGIC-LEVEL GOTCHA [ADVICE]
     Because the pull-ups go to the encoder VCC, powering the encoder from 5V
     probably gives 5V signals. On a 3.3V MCU (ESP32, RP2040, most STM32 pins
     that aren't 5V-tolerant), power the encoder from 3.3V, or level-shift.
     Measure the signal high level with a scope before connecting.

  Stall power             18 W               14.4 W
  Operating temp          -10 to +70 C (supplier claim; "24-hour use")
  Noise                   ~55 dB (conditions unspecified)

  Driver sizing [ADVICE]
   - Pick an H-bridge rated for at least the stall current continuously, with
     margin: >=2A for 12V, >=1A for 24V. Inrush at start-up is close to stall
     current.
   - Examples that fit: DRV8871, DRV8833 (12V only, 10.8V max, so marginal),
     TB6612FNG (12V only, 15V max), L298N (works but inefficient), BTS7960
     (overkill). For 24V use one rated for >=30V, e.g. DRV8871 (45V max) or
     DRV8876.
   - Put a 100nF ceramic across the motor terminals (and optionally 2 x 47nF
     to the case) to cut brush noise.

  Supplier operating rules
   - Choose the motor by rated-load torque, not stall torque.
   - Don't stall the motor or run it close to stall. It can damage the motor
     or strip the gears.
   - Stop before reversing direction.
   - Lowering speed electrically does not increase torque the way a higher
     gear ratio does.

4. ENCODER: SIGNAL SPEC AND MATHS
--------------------------------------------------------------------------------
  [SUPPLIER]
   Type                 Magnetic incremental, AB quadrature square wave
   Magnet               22 poles (11 pole pairs)
   Pulses               11 pulses per MOTOR rev, per channel
   Per output rev       11 x gear_ratio pulses, per channel
   Response frequency   100 kHz (supplier figure)
   Speed formula        RPM_out = f_Hz x 60 / (11 x gear_ratio)
                        (f_Hz = full pulses per second on ONE channel)

  [DERIVED] Counting modes
   x1 (rising edges, one channel)   11  counts / motor rev
   x2 (both edges, one channel)     22  counts / motor rev
   x4 (all edges, both channels)    44  counts / motor rev   <- use this

   General: RPM_out = counts_per_s x 60 / (CPR_motor x gear_ratio)
            where CPR_motor = 11, 22 or 44 depending on mode.

  [DERIVED] Maximum signal rates (encoder is on the motor shaft, so these are
            the same for every gear ratio)
   Motor at 6000 RPM (no load)  = 100 rev/s
     Per-channel frequency      = 1100 Hz
     x4 edge rate               = 4400 edges/s  (~227 us between edges)
   Motor at ~4800 RPM (rated load point, e.g. 1100/4.4 or 9.6x500)
     Per-channel frequency      ~ 880 Hz

   ordinary GPIO interrupts can keep up. A hardware counter is still better.

5. FIRMWARE IMPLEMENTATION NOTES  [ADVICE]
--------------------------------------------------------------------------------
  5.1 Counting hardware (use a peripheral, not ISRs, where you can)
   STM32     TIMx in encoder mode (TI12, x4). Enable the input filter (ICxF).
   ESP32     PCNT unit with glitch filter (~1 us), or the ESP-IDF
             pulse_cnt driver.
   RP2040    PIO quadrature encoder program (pico-examples).
   AVR       Pin-change interrupts; fine at these rates, but costs CPU.
   Use a 32-bit (or extended 16-bit) accumulator. With the 500:1 gearbox,
   x4 is 22000 counts per output rev, so a 16-bit counter wraps in under
   3 revs.

  5.2 Speed estimation
   The encoder is low-resolution (44 counts per motor rev), so:
   - Count-in-window (M-method): at 4400 edges/s, a 1 ms window gives only
     about 4 counts (~25% quantisation). Use a window of 10 ms or more (~44
     counts, ~2%), or a moving average.
   - Edge-period timing (T-method): time the gap between edges with a capture
     timer. Better at low speed. Add a timeout so that "no edge for X ms"
     reads as 0 RPM.
   - Practical choice: M/T hybrid, or M-method with a 10-20 ms velocity loop
     and a low-pass filter.
   In plain terms: at a fast control-loop rate you don't see enough ticks to
   measure speed precisely, so either measure over a longer window or time
   the gap between ticks.

  5.3 PWM
   [UNKNOWN] The supplier gives no PWM frequency limits.
   Typical: 15-25 kHz (above hearing; fine for small brushed motors). Lower
   frequencies (1-5 kHz) give more low-speed torque but whine.
   Keep within the driver's limits and dead-time requirements.
   Expect a deadband: the motor won't turn below roughly 5-15% duty. Find it
   on the bench and compensate in the controller.

  5.4 Direction changes
   The supplier says to stop before reversing. Implement a ramp to zero,
   optionally a short brake (both low-side on, or the driver's brake mode),
   then reverse. Don't snap from +100% to -100%.

  5.5 Protection
   - Stall detection: PWM above a threshold while encoder speed stays near 0
     for more than ~200-500 ms means cut power, set a fault, and back off.
   - If the driver has current sensing, set the trip point well below stall
     (e.g. ~1.0 A sustained on the 12V version, ~0.4 A on 24V).
   - Encoder-loss detection: commanded motion with no counts means a fault.
     Watch for a wiring fault before PID integral wind-up drives the output
     to full.
   - Soft-start / slew limit on the PWM to limit inrush.

  5.6 Noise
   Brush commutation is electrically noisy. Twist the encoder wires, keep them
   away from the motor leads, use the MCU's digital input filter, and add a
   small RC (e.g. 100-470 ohm + 1 nF) at the MCU input if you see glitches.

  5.7 Control loop
   Cascade: position (P/PD) -> velocity (PI) -> PWM. Feed-forward on velocity
   helps a lot with the deadband. Anti-windup on the integral term.
